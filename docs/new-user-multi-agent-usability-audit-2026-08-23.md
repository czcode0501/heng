# 衡策 Quant Desk 新手多角色使用与可用性审计

日期：2026-08-23  
测试对象：当前 `main` 工作区、本地数据 API、Vite 浏览器界面  
目标用户：没有股票投资经验、希望通过软件降低决策难度并控制亏损的普通用户

## 1. 执行摘要

衡策目前最有价值的能力不是行情、持仓或盈亏展示，而是把研究翻译为五个动作问题：

1. 现在做什么；
2. 在什么价格区间考虑买入或卖出；
3. 买多少；
4. 需要等待什么确认；
5. 什么情况说明判断错了。

这套“行动—区间—数量—等待条件—失效位”结构明显区别于普通券商行情页，也是最值得继续投入的产品核心。

当前版本仍不能被视为完全适合投资小白。最高风险不是程序崩溃，而是产品表达可能让新手在数据不足时过度相信精确数字：实测 AAPL 页面一度同时出现“未知·数据不足”“覆盖率 30%”“置信度低”“等待”“当前不新增仓位”，但仍展示精确买入区、卖出区、失效位和 `13.66 : 1` 收益风险比。警告与数字同时出现时，新手通常会记住数字。

另一个严重冲突是：个股结论为“等待、当前不新增仓位”时，页面仍提供“添加到组合”，随后允许用户按当前价格填写建仓数量。观察、研究计划和真实持仓之间的语义没有完全隔离。

产品定位建议：

> 衡策应成为“不会替用户下单、但会把复杂研究翻译成可执行风险纪律”的工具，而不是另一个券商终端。

## 2. 测试方法

本轮由一个总控测试者和三个并行角色完成：

| 角色 | 年龄/行业 | 投资经验 | 核心关注 |
|---|---|---|---|
| 年轻职场新手 | 25岁，互联网运营 | 首次买股 | 路径清晰、能否告诉我买什么和买多少 |
| 忙碌经营者 | 43岁，餐饮小企业主 | 金融知识有限 | 省时间、明确行动、避免大亏 |
| 退休保守用户 | 66岁，退休教师 | 只接受长期低风险 | 可读性、长期逻辑、权威误导、安全感 |
| 总控验收 | 产品与集成视角 | 按新手操作 | 真实浏览器、跨模块冲突、定位去重 |

真实浏览器路径包括：

- 首页空组合；
- 搜索 AAPL，并区分 Apple 与相似 ETF；
- 个股行情、财报、新闻、经理解读四个标签；
- 五类模型信号目录；
- 数据源中心；
- IBKR 只读连接说明；
- 桌面与 390px 窄屏；
- 控制台警告与横向溢出检查。

本轮没有提交券商账户、API Key 或真实交易，也没有把自动化测试当作在线数据正确性的证明。

## 3. 实测结果

### 3.1 可用性与技术状态

- 桌面与 390px 页面没有全局横向溢出；390px 时 `innerWidth=390`、文档滚动宽度为 375。
- 个股弹窗在 390px 下位于视口内，内容宽度没有溢出弹窗。
- 宽表格存在局部横向内容，但由容器承载，没有扩大整个页面。
- 浏览器控制台未发现 warning 或 error。
- 搜索可把 Apple Inc. 与 Roundhill AAPL WeeklyPay ETF 分开显示。
- 数据源页面明确区分延迟、收盘后、估算、未配置和只读状态。
- 宏观、市场择时、板块轮动、投资者情绪、资金流向、微观数据和组合对比七个正式路由均能在真实浏览器中加载。

### 3.2 AAPL 新手决策实测

页面正确地先展示：

- 行动：等待；
- 买入区；
- 卖出区；
- 当前不新增仓位；
- 等待止跌确认；
- 收盘跌破后的判断失效位。

优点是动作顺序清楚，而且多次说明“只读计划，不会自动提交券商订单”。

问题是数据加载过程和低覆盖状态下仍可能显示高精度价格与回报比。对于没有模型知识的用户，“精确到分的价格”和“两位小数的收益风险比”具有强烈权威感，可能压过“低置信度”。

### 3.3 财报、新闻与经理解读

- 财务数据明确标识 SEC EDGAR Companyfacts 来源，空值不推算。
- 官方披露和媒体新闻分开；媒体 API 未配置时不会把零条新闻解释成公司没有新闻。
- 经理解读明确显示 B 级、待双源核验以及 `0/8` 公司研究维度有证据。
- 同一事实不会随经理切换而改变。

主要问题：长期基本面证据为 `0/8`、估值与未来预期均待补证时，技术页仍能展示精确交易区间。长期新手可能误以为技术价格已经替代了基本面研究。

### 3.4 券商与数据源

IBKR 页面在安全表达上表现良好：

- 只允许回环地址；
- 不收用户名和密码；
- 明确端口和 Client ID；
- 不保存资金账号；
- 没有下单端点。

但这条路径对目标小白并不友好。用户必须理解 TWS、IB Gateway、Socket API、7496/7497、Client ID 和多账户选择。普通新手通常只有手机券商 App，不会安装 TWS API Python 客户端。

因此券商连接应是高级的“持仓数据导入”，不应成为新手首屏的主要任务之一。

## 4. 优点

### 4.1 产品优点

1. 新手五步卡直接回答行动问题，方向正确。
2. 缺失数据不会自动变成零分、负面判断或买入建议。
3. 明确区分估算订单流和真实逐笔成交。
4. VRVP 明确不是交易所真实挂单墙。
5. 真实券商账户与自建研究组合在数据合同上分离。
6. 经理切换改变方法论，不篡改事实数据。
7. 搜索、分析和添加持仓相互解耦，便于先研究。
8. 颜色状态同时有文字，不完全依赖红绿颜色。
9. 390px 没有页面级横向溢出。
10. 公司事实、官方披露、媒体新闻和证据等级具有较好的来源纪律。

### 4.2 相对券商 App 的差异化优势

- 券商告诉用户“持有什么、赚了多少”；衡策可以解释“为什么继续持有、什么会推翻判断”。
- 券商提供订单入口；衡策可以提供下单前风险纪律。
- 券商重视实时价格；衡策可以重视证据缺口、数据冲突和复核节奏。
- 券商通常不阻断用户下单；衡策可以在证据不足时拒绝生成交易计划。
- 衡策可以统一处理中美市场、方法论差异和持仓论文。

## 5. 缺点与痛点

## 5.1 P0：应在继续扩展功能前修复

### P0-1 等待状态仍能进入“建仓数量”流程

现象：结论为“等待、当前不新增仓位”时，仍可点击“添加到组合”，并按当前价记录数量。

风险：新手会把“加入组合”理解为平台允许或建议买入，绕过风险硬门槛。

建议：

- 拆成“加入观察池”和“记录已持仓”两个动作；
- 等待状态默认只允许加入观察池；
- “记录已持仓”必须说明这是券商已经成交后的记账，不是衡策下单；
- 录入价格偏离建议区或与当前动作冲突时显示强警告；
- 不使用含糊的“添加”。

### P0-2 低覆盖状态仍展示伪精确交易数字

现象：覆盖率 30%、低置信度、宏观/择时/情绪不可用时，仍显示精确买卖价和收益风险比。

建议：

- 关键层缺失或覆盖率未达门槛时，隐藏交易区间、回报比和建议数量；
- 改为“当前不能形成可靠交易计划”；
- 数据恢复后再解锁数字；
- 所有精确数字同时显示数据日期、样本区间和估算属性。

### P0-3 缺少新手首次风险适配

现象：默认目标年化 12%、风险 50/100、默认持有 3 个月；最长持有期 365 天。

风险：默认值容易被理解为平台推荐，且不适合退休、长期或极保守用户。

建议首次使用先询问：

- 这笔钱多久不会使用；
- 是否已经保留应急资金；
- 最大可接受人民币亏损；
- 最大可接受回撤百分比；
- 投资期限；
- 是否已有真实持仓。

问卷完成前不生成目标仓位和精确建议股数。

### P0-4 固定美元汇率影响金额与股数

当前代码使用固定 `USD/CNY = 7.18`。这会影响总资产、仓位缺口和跨币种建议数量。

建议：

- 接入带来源与时间戳的汇率；
- 汇率过期时禁止给出跨币种精确股数；
- 允许用户选择组合本位币；
- 明确汇率只用于研究折算，不等于券商实际换汇价格。

### P0-5 只读定位与自动交易路线文案冲突

共同规则和 README 说明自动交易不在当前范围，但数据源视图仍出现“自动交易仍在搭建”“模拟订单→用户确认下单→有限自动化”。

建议删除该路线，统一为：

> 衡策是只读研究与持仓复核工具；交易执行不在产品范围。

## 5.2 P1：直接影响新手留存和信任

### P1-1 没有真正回答“我先看哪只股票”

首页要求用户先知道股票代码或名称。全市场扫描器只有 CLI 输出，没有面向普通用户的候选入口。

建议提供“今日待研究”而不是“今日推荐”：

- 最多 3 个候选；
- 为什么进入候选；
- 哪些数据仍缺失；
- 什么情况不应参与；
- 一键进入个股分析；
- 明确候选不等于买入清单。

### P1-2 首屏与个股页信息密度过高

零持仓首页仍连续展示 KPI、仓位图、经理、五类模型入口。个股页五步之后还有期限、摘要、经理、证据层、价位、行动步骤、指标和复杂图表。

建议提供默认“新手简明模式”：

- 首屏只显示一个当前任务和一个主按钮；
- 个股默认只显示五步、一个核心原因和一个最大风险；
- 技术指标、方法论与数据诊断默认折叠；
- 专业模式保留完整信息。

### P1-3 术语和中英文混排增加理解成本

包括 VRVP、OHLCV、VWAP、RSI、MACD、POC、Impulse、Regime、Client ID、风险暴露等。

建议：

- 首次出现时使用中文白话；
- 提供一句话解释和“为什么重要”；
- 新手模式隐藏英文眉题；
- 把“失效位”解释为“收盘跌破就说明原判断错了”。

### P1-4 基金经理人物产生权威幻觉

名人姓名、头像和研究分的视觉权重高于免责声明。

建议：

- 主名称改为“质量价值方法”“深度价值方法”等流派；
- 人物仅作为公开方法论来源；
- 在结论同层常驻“非本人、非授权、非真实持仓”；
- 头像降级，不将人物作为主要购买理由。

### P1-5 小字可读性不足

部分正文和信号细节为 10–13px，个别复杂区域更小。没有横向溢出不等于易读。

建议：

- 正文默认不低于 16px；
- 辅助文字不低于 14px；
- 交互目标至少 44px；
- 增加大字模式；
- 对浅灰文字执行 WCAG 对比度检查。

### P1-6 数据源页混合了普通用户与专业配置

新闻 Key、券商、专业行情、Databento、FIX 和未来路线同时出现。

建议：

- 顶部明确“普通用户保持免费模式即可”；
- 默认折叠所有高级配置；
- 将“媒体新闻”“券商持仓导入”“专业行情”拆成独立高级设置。

### P1-7 信号目录仍有过时文案

实测目录显示“结构已建立·等待定义”，宏观信号描述也写“等待定义”，但模块已经实现。

影响：用户会怀疑整个软件只是静态原型。

建议依据当前代码和数据合同更新文案，不使用未来规划替代真实状态。

### P1-8 空组合在不同页面的现金口径冲突

实测空组合在总览显示“现金 100.0%”，在组合对比页面却显示“现金 0.0%”，同时仍出现“当前收益领先”和排名第 1。

影响：用户会怀疑资产计算是否可靠；只有一个空组合时使用“领先”和排名也没有决策意义。

建议：

- 统一空组合现金口径；如果没有录入初始现金，应显示“尚未设置”，而不是 0% 或 100%；
- 少于两个有效组合时隐藏领先结论和排名；
- 只有建立可比较的本金、起始日和持仓后才开放绩效比较。

## 5.3 P2：中期产品优化

1. 提供 CSV/手工持仓导入，降低 IBKR/QMT 门槛。
2. 把“券商账户”从首页第三步改为“可选：导入真实持仓”。
3. 创建组合时提供长期投资、定投、红利、试仓等纪律模板。
4. 为组合生成每天最多 3 项风险待办，而不是展示全部指标。
5. 组合对比增加相同起始日、波动、最大回撤和现金比例，避免追逐短期冠军。
6. 建立“判断—执行—复核—失效”的决策日志。
7. 长期模式默认打开基本面与持仓论文，不以短期技术区间为首页。
8. 财务表解释季度、累计、TTM、审计和修订口径。
9. 移动端考虑底部任务导航，减少侧栏图标含义猜测。

## 6. 与券商功能的重叠分析

| 能力 | 券商通常更强 | 衡策是否应继续投入 |
|---|---|---|
| 实时报价 | 是，数据授权更权威 | 只需可靠输入和状态标识，不做主卖点 |
| 下单、撤单、成交 | 是 | 不投入，保持只读 |
| 持仓、现金、盈亏 | 是 | 只做只读导入，避免重复录入 |
| K线和常用技术指标 | 是 | 保留为证据，不做通用行情终端竞争 |
| 新闻资讯 | 券商覆盖通常更广 | 只保留可追溯证据与缺口管理 |
| 为什么等待 | 通常较弱 | 重点投入 |
| 最大可买数量与最大亏损 | 通常不以研究纪律呈现 | 重点投入 |
| 判断失效条件 | 通常较弱 | 重点投入 |
| 数据冲突与待补证 | 通常较弱 | 重点投入 |
| 持仓论文与定期复核 | 通常较弱 | 重点投入 |
| 多方法论对同一事实的比较 | 通常没有 | 重点投入，但弱化名人背书 |

结论：券商连接的价值是减少持仓录入并取得权威账户事实，而不是复制券商账户页。衡策的价值应在连接后才开始：找出最危险持仓、解释证据缺口、计算风险上限、提醒复核和记录判断是否兑现。

## 7. 推荐的新手主流程

```text
首次风险问卷
    ↓
选择：研究一只股票 / 导入已有持仓 / 查看今日待研究
    ↓
数据充分性闸门
    ├─ 不充分：只显示缺口、等待原因和下一步
    └─ 充分：显示行动、区间、最大数量、等待条件、失效位
    ↓
加入观察池 或 记录券商已成交持仓
    ↓
每日最多 3 项风险待办
    ↓
到期复核投资论文与失效条件
```

## 8. 建议维护顺序

### 第一阶段：先消除误导风险

1. 分离观察池与真实持仓录入。
2. 低覆盖时隐藏精确交易计划。
3. 删除自动交易路线文案。
4. 修复信号目录“等待定义”。
5. 停止使用固定汇率生成精确建议数量。

### 第二阶段：建立新手安全闭环

1. 首次风险问卷。
2. 最大亏损驱动的建议股数。
3. 新手简明模式和大字模式。
4. 今日待研究和持仓风险待办。
5. 决策日志与复核日历。

### 第三阶段：验证产品是否真的有效

1. 无前视偏差的历史回测。
2. 样本外验证、交易成本和退市样本。
3. 公布样本量、命中率、最大回撤和失效分布。
4. 通过真实新手任务测试衡量完成率、理解率和错误率。

## 9. 建议验收指标

- 80% 新手能在 3 分钟内区分“观察池”和“真实持仓”。
- 90% 新手能复述当前动作、最大亏损和判断失效条件。
- 数据不足时，0% 用户误以为页面给出了可执行买入建议。
- 90% 用户知道衡策不会下单，交易仍需在券商完成。
- 80% 用户不需要理解 VRVP、VWAP、MACD 就能完成核心任务。
- 390px 无页面级横向溢出，正文和交互目标满足可读性要求。
- 券商连接失败时，不丢失研究组合，也不使用免费行情冒充券商账户字段。

## 10. 总结

衡策已经具备一个优秀新手投资纪律工具的骨架：行动明确、证据诚实、只读安全、缺失不造数。当前阻碍它成为真正新手产品的，是观察与持仓边界不够清楚、低置信度下的伪精确、默认风险参数、术语密度和券商终端拟态。

下一阶段不应优先增加更多行情、指标或交易功能，而应让用户更少犯错：不知道时明确等待，数据不足时不生成计划，准备买入时先计算最大可承受亏损，持有后持续检查原判断是否失效。
