# 衡策 Quant Desk 新手化改造：可执行提示词包

用途：复制其中一条提示词，分别交给对应专题对话执行。每个专题对话只修改自己负责的模块；跨模块问题先形成接口或交接清单，由项目总控统一集成。

## 一、三个核心问题的独立提示词

### 提示词 1：降低信息密度，按更新频率重组页面

你负责衡策 Quant Desk 的信息架构与页面密度改造。目标用户是没有投资经验、第一次使用股票研究软件的普通用户。

开始前必须阅读 `AGENTS.md`、`README.md`、`package.json`、Git 状态、`index.html`、`app.js`、`styles.css`、相关 view/model 文件和现有测试。不要假设功能存在，也不要覆盖其他专题对话的未提交成果。

当前问题：页面把日内、每日、每月、季度、年度数据同时完整展开。季度财报、经理方法论、数据源诊断等低频内容长期占据主页面，使新手无法找到“现在该做什么”。

请完成：

1. 盘点所有主要页面信息块，标记其更新频率：盘中、每日、每周、每月、季度、事件触发、仅配置时查看。
2. 按“行动优先、风险其次、原因第三、原始数据最后”重新设计信息层级。
3. 首页默认只展示：现在做什么、最重要风险、下一步、最多三项待办。
4. 个股页默认只展示：行动、买卖区间、最大可买数量、等待条件、失效位、数据是否足够。
5. 季度财报、完整指标表、经理方法论详情、数据源诊断默认折叠；只有数据更新、出现冲突或用户主动展开时提高视觉权重。
6. 为“最近有变化”和“几个月没有变化”设计不同状态，不重复用整张表占据首屏。
7. 保留专业模式，确保信息没有被删除，只是按频率和任务重新组织。
8. 桌面端和 390px 窄屏都要实测，不允许页面级横向溢出。

交付物：现状信息地图、改造后的页面层级、实际代码、聚焦测试、`npm test`、`npm run build`、真实浏览器桌面与 390px 验证记录。

验收标准：新手在 10 秒内能说出当前动作和最大风险；季度数据不再长期占据首屏；专业用户仍能在两次点击内查看完整证据。

### 提示词 2：把投资经理蒸馏能力变成产品主亮点

你负责把衡策 Quant Desk 的“可切换投资经理/投资流派”从隐藏的专业功能升级为核心产品体验，但不能制造名人授权、真人建议或收益承诺。

开始前必须阅读 `AGENTS.md`、`README.md`、`portfolio-managers.js`、`portfolio-manager-contract.js`、`portfolio-manager-view.js`、`portfolio-manager-insights.js`、`portfolio-manager-methodology.js`、`signals/stock-analysis/company-research.js`、`docs/investor-manager-audit.md`、对应测试和 Git 状态。

当前问题：经理切换虽然已经影响因子、门槛、仓位和解释，但新手在首页和个股主路径中感受不到“同一事实、不同方法会得出什么不同结论”。人物头像和长方法论说明反而可能造成权威幻觉。

请完成：

1. 将经理首先表述为“投资方法”，例如质量价值、深度价值、合理价格成长、周期防守、趋势反馈；人物姓名作为公开方法论来源放在次级位置。
2. 在同一只股票上用一张简洁对比卡展示：各方法最看重什么、当前结论、最大仓位、最担心什么、什么情况会改判。
3. 默认只突出当前方法与另外一个差异最大的反方方法，完整八种方法放入展开层，避免一次展示八份长文。
4. 在首页明确回答“为什么选择这个方法适合我的目标和风险”，不要只显示经理名字。
5. 把方法差异落实到行动、首笔仓位、等待条件和退出纪律，而不是只改变语气。
6. 证据不足时必须显示“此方法无法形成结论”，不能用技术信号冒充基本面判断。
7. 在每个经理结论同层常驻：公开方法论映射、非本人观点、非授权、非真实持仓、非收益承诺。
8. 设计首次选择引导，用生活化问题匹配方法，但不得宣称这是适当性建议。

交付物：经理体验信息架构、同事实对比组件、首次选择流程、实际代码、差异化测试、浏览器验证和方法论诚信检查。

验收标准：新手能用一句话解释当前方法与另一方法的区别；切换方法必须产生可审计的行动或风险纪律差异；不把人物名气当作买入理由。

### 提示词 3：全站专业术语大白话改造

你负责衡策 Quant Desk 的新手语言系统。目标是在不牺牲准确性的情况下，让没有金融背景的用户第一次阅读就能理解。

开始前必须扫描全站可见文案、ARIA 标签、错误状态、图表说明和测试，建立术语清单。重点包括 VRVP、VWAP、RSI、MACD、OHLCV、POC、Regime、Impulse、风险暴露、回撤、流动性、资金背离、证据闸门、Client ID 等。

请完成：

1. 建立“专业名词 → 页面主文案 → 次级专业名词 → 一句话解释 → 用户行动”的词典。
2. 页面主文案优先使用大白话；专业名词放在括号、帮助提示或专业模式中。
3. 每段解释都回答“这是什么意思、为什么重要、我该做什么”，不要只给定义。
4. 示例：
   - 失效位 → “收盘跌破这个价格，说明原来的判断可能错了”；
   - 市场风险暴露 60%–80% → “当前最多考虑把六到八成资金放在风险资产，其余保留现金”；
   - 资金背离 → “价格在涨，但成交资金没有跟上，上涨可能不稳”；
   - VRVP → 主文案使用“历史成交密集区”，专业名放在次级说明；
   - 数据覆盖率 30% → “十项关键信息中大约只有三项可用，暂时不能形成可靠计划”。
5. 清理不必要的英文眉题和中英文重复，不用英文制造专业感。
6. 错误、等待、不可用、过期和待补证状态必须告诉用户下一步。
7. 保留专业模式中的准确术语，确保大白话没有改变模型含义。
8. 更新测试，防止专业术语重新进入新手主界面。

交付物：术语词典、全站文案修改、可访问性标签修改、文案回归测试、桌面和 390px 浏览器验证。

验收标准：邀请没有金融背景的人阅读核心页面，80% 能正确复述当前动作、原因、最大风险和下一步；不能通过删掉风险限定语来换取“易懂”。

## 二、按部门划分的单独执行提示词

### 部门 1：审查 Quant Desk 项目状态

你是衡策 Quant Desk 的项目总控与集成验收负责人。请先阅读 `AGENTS.md`、`README.md`、`package.json`、Git 状态、核心文档、API 路由、前端入口和测试，建立“已实现、部分实现、未来规划”三栏基线。

本轮总目标是协调三项改造：降低信息密度、突出投资方法蒸馏、全站大白话。你的职责不是替专题部门完成全部 UI，而是：

1. 建立页面—模块—数据源—测试—责任部门依赖图。
2. 标记日内、每日、月度、季度和事件型数据，决定哪些内容可进入首屏。
3. 维护统一的新手主流程和跨部门接口合同。
4. 审核“经理方法”是否真实改变行动、仓位和风险纪律。
5. 审核大白话是否保持原模型含义和风险限定。
6. 检查观察池、研究组合、券商真实持仓之间的冲突。
7. 对所有专题成果运行完整测试、构建和真实浏览器验收。
8. 更新 README 和功能状态，但不得把规划写成已上线。

必须输出：当前基线、冲突清单、部门交接清单、P0/P1/P2 验收结果、未完成项。不得在未检查代码的情况下宣称功能存在。

### 部门 2：添加衡策 Quant Desk 项目规则

你负责维护 `AGENTS.md` 和项目级设计/开发规则。请检查当前代码和已有规则后，补充支持本轮新手化改造的约束，但不要写空泛口号。

规则必须覆盖：

1. 首屏只放高频行动与风险；低频季度数据默认折叠。
2. 页面信息顺序统一为“行动→风险→原因→原始证据”。
3. 专业术语不得直接作为新手主标题，必须有大白话主文案。
4. 投资经理首先是方法论模板，人物仅作为公开来源，不得暗示授权或收益。
5. 数据不足时隐藏精确交易计划，不用精确数字制造信心。
6. 观察池、研究持仓和券商真实持仓必须使用不同名称与动作。
7. 自动交易不在范围；不得出现未来自动下单路线文案。
8. UI 修改必须检查桌面、390px、字号、对比度和触控面积。
9. 每个专题只能修改责任范围，跨模块先交给总控。
10. 规则必须能够由测试或验收步骤验证。

交付前运行相关文档/契约测试，并列出每条新规则对应的检查方法。

### 部门 3：统一视觉品牌与经理头像

你负责衡策 Quant Desk 的视觉层级、品牌和投资方法视觉表达。不要修改模型计算、数据源或券商合同。

目标：降低页面拥挤，让当前行动和风险首先被看见，同时突出“同一事实、不同投资方法”的产品亮点，避免名人头像形成权威背书。

请完成：

1. 建立四级视觉层级：当前行动、最大风险、方法差异、完整证据。
2. 低频季度数据和完整表格使用折叠、更新时间摘要和“有变化”提示。
3. 新手模式正文至少 16px、辅助文字至少 14px、主要点击目标至少 44px。
4. 减少英文眉题、全大写标签、装饰性数字和同时竞争注意力的卡片。
5. 投资方法名称比人物头像更突出；头像缩小为来源标识。
6. 每个方法使用一致的卡片结构，不用颜色暗示某位经理更可靠。
7. 状态不能只靠红绿颜色；必须配合文字和图标。
8. 验证浅色、深色、桌面和 390px，不得出现页面级横向溢出。

交付物：视觉层级规范、组件改造、前后对比、可访问性检查、浏览器验证。不得用删除风险说明来换取简洁。

### 部门 4：优化金融新手决策 UI

你负责新手核心路径：首页、搜索结果、个股决策卡、观察池/持仓录入和每日待办。不要修改底层模型权重或数据源实现。

请围绕三个目标实施：减少密度、让投资方法差异可见、全面使用大白话。

重点修复：

1. “等待/不新增仓位”时仍可按当前价添加持仓的冲突。
2. 将“添加”拆成“加入观察池”和“记录已持有”。
3. 数据覆盖不足时隐藏精确买卖价、回报比和建议股数。
4. 首次使用先完成风险问卷，再生成目标仓位和最大可买数量。
5. 首页只给一个当前动作、一个最大风险、一个主按钮和最多三项待办。
6. 提供“今日待研究”，但明确不是推荐或买入清单。
7. 个股默认只显示行动、买卖区间、最大数量、等待条件、失效位；完整技术证据折叠。
8. 用大白话替换 VRVP、风险暴露、资金背离等主文案。
9. 当前投资方法必须说明“为什么适合这个目标”和“另一方法会怎么不同”。
10. 记录操作不能冒充券商成交，软件不能自动下单。

验收：用空组合、等待股票、买入股票、数据不足、已有持仓五种场景测试；完成桌面、390px、键盘操作、完整测试和构建。

### 部门 5：完善投资经理研究阀门

你负责投资方法合同、公司研究证据闸门、经理差异和持仓论文。不要负责全站视觉，也不要修改券商连接。

请完成：

1. 把八位经理映射为清楚的投资方法名称，人物作为来源说明。
2. 为每种方法定义形成结论所需的最小事实、阻断条件和退出条件。
3. 证据不足时返回“不能形成结论”的结构化状态，供 UI 隐藏精确交易计划。
4. 保证基本面方法不会被技术指标替代，达利欧不会输出单股全天候仓位。
5. 生成同一事实下最多两种方法的关键差异：关注点、行动、最大仓位、最大担忧、改判条件。
6. 将长篇方法论压缩为新手能理解的一句话，同时保留完整专业解释。
7. 持仓论文必须包含 3–7 条可证伪假设、复核时间和红线；没有基线不得生成健康分。
8. 在每个输出中带来源版本、证据等级、非本人观点和非收益承诺标识。

必须新增行为差异、缺失证据、双源冲突、论文复核和大白话映射测试。不得只改变经理语气。

### 部门 6：维护 IBKR / QMT 只读持仓

你负责券商只读持仓、真实账户总览和研究组合之间的数据边界。不要实现下单、撤单或自动交易。

目标：把券商从“新手必须配置的功能”改成“可选的真实持仓数据导入”，并减少与券商 App 的重复。

请完成：

1. 首页将券商入口改为“可选：导入真实持仓”，不作为新手第三个必做步骤。
2. 清除“自动交易仍在搭建”“模拟订单→自动化”等冲突文案。
3. 用大白话解释 TWS、Gateway、Socket 端口和 Client ID；提供逐步检查和错误修复指引。
4. 明确区分“研究计划（可编辑）”与“券商实盘（只读、真实资产）”。
5. 缺失券商字段保持不可用，不用免费行情或估算值回填。
6. 券商连接的主要输出应是持仓风险复核、失效位距离和每日待办，而不是复制行情/盈亏终端。
7. 评估增加 CSV/手工导入作为普通用户低门槛替代方案；未实现前只写成规划。
8. 不保存密码、资金账号、持仓和敏感路径；只保留已批准的最小回环连接配置。

运行券商合同、安全、总览、失败降级测试，并在无 IBKR/QMT 环境时验证新手仍可完整使用研究功能。

### 部门 7：维护五层信号与行情系统

你负责宏观、市场择时、板块轮动、投资者情绪、资金流向、微观数据及共享行情。不要负责组合录入或券商下单。

目标：保留模型完整性，但把输出变成新手能理解、按更新频率展示的证据，而不是堆满指标。

请完成：

1. 为每个信号声明更新频率、数据截止日、来源、缓存状态和下次可能变化时间。
2. 页面默认只显示一句大白话结论、为什么、对用户行动的影响、最大不确定性。
3. 原始指标、权重、历史图表和诊断默认折叠到专业层。
4. 月度和季度数据没有变化时只显示摘要；更新或异常时才提高视觉权重。
5. 将专业名词映射为大白话，例如资金背离、市场风险仓位、情绪拥挤、成交量不足。
6. 不把五层相关指标重复计权；资金流进入板块轮动仍只保留去重后的确认维度。
7. 数据缺失、过期或低可信时输出结构化阻断状态，供个股 UI 隐藏精确交易计划。
8. 修复“结构已建立·等待定义”等过时文案，使目录与当前实现一致。
9. 解释看似矛盾的评分，例如价格下跌但流动性维度高分，避免新手只看总分。
10. 不把 EOD、代理变量或估算订单流称为实时、机构净买入或真实挂单。

验收覆盖五个信号页面、微观数据、统一时间范围、缓存降级、桌面和 390px，以及大白话文案回归测试。

1. 修改文件清单；

未经总控集成验收，不得单独把跨模块成果写成全项目已完成。
